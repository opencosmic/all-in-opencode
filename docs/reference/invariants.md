# Invariants

| Invariant | Enforcement |
|---|---|
| Runtime code uses stock public OpenCode plugin and SDK APIs only. | Static dependency guard and loader test |
| Eighteen project-owned delegation tools are exposed, including the Executor-only `execution_preflight`, bounded `workspace_checkpoint_update`, three Producer-only production tools, restricted `consult_agents`, and six bounded Atlas media-runtime tools. | Plugin and runtime policy tests |
| Producer's production control plane uses one canonical manifest, safe physical path preparation, and one overwrite-only checkpoint; phase agents and Implementer categories cannot call its tools. | Production-control, contract, permission, and plugin tests |
| Category selection is deterministic and every enabled category routes to the shared Implementer. | CategoryEngine tests |
| Category ceilings are caller-specific: Assistant remains broad except for hard caller-exclusive categories, Executor may use only `implementation`, Producer uses `media` but cannot call `blender-previs`, and Director/Creator/Editor have exact bounded category sets; named-agent policy remains separate. | Delegation policy and catalog tests |
| The built-in family catalog keeps `git` and `blender-previs` in `implementation` and media categories in `media`; built-in family labels are canonical and cannot be reclassified through `aio.json`, while custom categories may choose their own family. | CategoryEngine and AIO-config tests |
| Named delegation is fail closed: effective OpenCode discovery gates existence, AIO opt-in and caller lists gate custom agents, and workflow-specific built-in ceilings remain hard. | Delegation policy tests |
| `consult_agents` is Implementer-only, accepts only bounded Explorer/Librarian requests, waits for all outcomes in input order, and consultation children cannot recurse. | Consultation runtime, profile, and effective-agent permission tests |
| Ordinary Implementers cannot mutate Git topology or history. | Effective-agent permission test |
| Git and video capabilities are scoped to sessions launched through their exact categories; video additionally requires the explicitly selected `watch` skill. Browser capability is scoped to the dedicated Browser primary route, while `browser-testing` is a separate Implementer category with no special Browser-agent permissions. | Category permission, Browser agent, and browser-testing tests |
| Workspace identity is provenance-bound; release proves ancestry or patch equivalence and never forces cleanup. | WorkspaceManager tests |
| Background completion is durable and resumes an eligible parent once per terminal group. | Completion and host integration tests |
| Missing parent status is resumable only with a current-process idle witness. | Parent resume tests |
| OpenSpec `tasks.md` is the only durable formal-workflow progress source. | Prompt and command policy tests |
| Executor performs a mandatory current-state execution preflight before topology or implementation delegation. | Execution preflight and Executor policy tests |
| Planner task boundaries do not imply agent, branch, or worktree boundaries; one logical change reuses one primary workspace by default. | Change-centric workspace resolver tests |
| Workspace descriptions and one latest checkpoint are local advisory manifest metadata; they cannot override identity, ownership, Git facts, or workflow gates. | Workspace context, runtime ownership, and preflight tests |
| Checkpoints are bounded, overwrite-only, carry runtime-derived HEAD/timestamp, report simple HEAD freshness, and do not create history, event logs, or alternate durable workflow state. | Workspace context tests |
| Protected base branches such as `main` and `master` are never normal Executor implementation or Git-mutation targets. | Executor runtime and Git permission tests |
| Child worktrees require a concrete isolation reason and integrate into the primary change branch, never directly into the protected base. | Child workspace and cleanup tests |
| Technical Advisor advises and Plan Reviewer independently approves or rejects. | Agent policy tests |
| CodeGraph is a direct public MCP integration and only structural evidence. | Config and role-policy tests |
| Browser has a dedicated `/browser` route backed by the external `ego-browser` skill/runtime; it is not an Implementer category, and Assistant-to-Browser delegation is not enabled. Technical web verification instead uses the separate `browser-testing` Implementer category and external `agent-browser` CLI guidance. | Browser agent, category-removal, and browser-testing tests |
| Blender is an all-mode reusable 3D leaf backed by external Blender MCP; `/blender` and `Executor -> Blender` share one specialist, it is not a CategoryEngine category, uses an explicit five-tool MCP allowlist, receives no category catalog, and cannot delegate child AIO tasks. | Blender agent, delegation, provisioning, catalog, and discovery tests |
| Video production has a dedicated `Producer` + `/video` primary route backed by the external upstream HyperFrames skill family; `/film` sends planning and previs through Director, while Producer prepares paths and owns state; Producer delegates Director, Creator, and Editor, but not named Blender. | Producer-agent, delegation, category-permission, command, and provisioning tests |
| `blender-previs` is a Director-only built-in Implementer category in family `implementation`; it exposes only the existing five Blender MCP tools, produces lightweight `.blend`/stills/preview evidence, and cannot use Atlas/media-generation, shell, direct filesystem, or delegation capabilities. | Blender-previs category, policy, catalog, permission, film-production, and Producer tests |
| Advanced `/film` production uses the same Producer, loads the repository-owned `film-production` skill before HyperFrames composition, and routes through validated `ShotSpec`/`ProductionManifest` contracts. | Film-production contract, discovery, routing, and Producer tests |
| `media-generation` is a provider-neutral bounded Implementer category in family `media`; its Atlas runtime exposes only six explicit media tools and cannot delegate, use shell/Git, browse, edit files, or expose arbitrary HTTP/provider controls. | Media-generation category and Atlas runtime tests |
| Video-content questions remain separate: `video-analysis` uses the independent upstream `watch` skill, while `/video` owns HyperFrames production. | Producer-agent and existing watch/category tests |
| `/video` never silently updates global HyperFrames skills without approval; setup is explicit and the health check is read-only. | Producer-agent and HyperFrames provisioning tests |
| Searcher is a read-only `/search` route using bounded native web retrieval; Assistant/configured callers may delegate it as a named leaf, but it cannot delegate onward or enter Deep Research infrastructure. | Searcher integration and delegation-policy tests |
| Delegation tool convention is separate from target authority: orchestration agents (Assistant, Executor, Planner, Strategist, Producer, Director, Creator, Editor) may use `delegate_task` plus `task_status`/`task_output`/`task_cancel`, while Blender and other leaf specialists (Searcher, Browser, Explorer, Librarian, Reviewer, QA, Verifier, and similar roles) do not; `DelegationPolicy` still decides what may be delegated, and task ownership decides which existing child may be controlled. | Effective-agent, delegation-policy, and runtime tests |
| AIO task status/output/cancel operations are parent-session-owned; foreign task IDs fail with a generic authorization error without output or cancellation, and task lists remain parent-scoped. Each category-capable orchestrator receives only its caller-authorized category catalog; Blender, Searcher, and Browser remain catalog-free leaves. | Delegation runtime ownership and caller-catalog tests |
| Professor is a separate read-only primary `/research` route; ResearchState owns IDs, frontier ordering, evidence, contradictions, verification, persistence, and reports while native web retrieval remains direct. | Professor agent, runtime, plugin, persistence, and command tests |
| Video-content questions route to `video-analysis` plus the independent upstream `watch` skill; this remains separate from `/video` and `/film` production orchestration. | Video category, routing, and provisioning tests |
| OpenDesign is optional read-only design context: only an Implementer in `visual-engineering` plus selected `open-design` may execute generic MCP resource operations for the exact `open-design` server; raw sanitized OpenDesign tools remain denied and the current worktree remains authoritative. | OpenDesign integration and permission-boundary tests |
| The retired alternate runtime, config, command, agents, and continuation tools are absent. | Zero-dependency policy test |
